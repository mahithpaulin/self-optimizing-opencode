Why not the curl installer directly:
- The installer detects uname Linux/aarch64 and selects linux-arm64 (glibc).
- Android bionic cannot execute the glibc build.
- The official musl platform artifact is the supported Linux-musl build; it was
  extracted manually and launched with a musl ELF loader.
- The official installer would also target ~/.opencode/bin, alongside the existing V1
  installation, which was deliberately preserved.

Observed Termux-specific failure:
  $ opencode2 run --standalone ...
  Error: Standalone server exited before reporting readiness
  cause: process.execPath is the loader; self-spawn runs `ld-musl serve` and fails

Working official path used by this system:
  opencode2 serve --hostname 127.0.0.1 --port <port>
  opencode2 run --server http://127.0.0.1:<port> ...

No fork CLI is installed or used as V2. The V1 `opencode-termux` installation remains
untouched and still reports 1.19.3.
